# 기능 명세 — 종목 마스터 동기화와 국내 주요 공시 수집

작성일 `2026-11-25` · 상태 초안 · 제품 요구사항 [PRD.md](PRD.md)

## 1. 사용자 시나리오와 인수 조건

### US-01 · 시장별 최신 검증 목록을 확인한다 (P1)

개인 사용자는 국내·미국 종목 파일을 직접 내려받지 않고, 다섯 시장의 종목 데이터와 마지막 정상 수집 시각을 확인한다.

1. 다섯 시장의 정상 파일이 준비된 상태에서 일일 회차가 실행되면, 코스피·코스닥·나스닥·뉴욕·아멕스 목록과 시장별 처리 건수를 볼 수 있다. 최초 적재는 비교 기준을 만든다.
2. 국내·미국 시험본에 주식·ETF·ETN이 있으면 세 유형이 모두 조회된다. 코드·심볼과 종목명은 원본과 일치하고, 조회용 유형과 원본 증권 유형·상품 구분 코드를 함께 확인할 수 있다. `001`, `002`처럼 선행 0이 포함된 코드도 보존된다.
3. 한 시장의 다운로드나 검증이 실패하면, 해당 시장은 마지막 정상 목록과 정상 수집 시각을 유지한다. 다른 정상 시장은 갱신되며 회차 화면이나 운영 조회에서 실패 시장과 오류 이유를 확인할 수 있다.
4. 확인 가능한 원천 효력일은 수집 시각과 다른 항목으로 조회할 수 있다. 원천 효력일을 확인할 수 없으면 미확인으로 표시한다.

### US-02 · 실패한 회차를 재개한다 (P1)

운영자는 실패 시장의 입력과 처리 상태를 확인하고 같은 회차를 재개한다. 이 시나리오는 일부 시장이 반영된 상태에서 프로세스를 중단하는 시험으로 독립 검증한다.

1. 일부 시장이 성공한 뒤 남은 시장이 실패했다면, 같은 회차를 재실행해 성공 시장을 건너뛰고 실패 시장을 처리할 수 있다. 원본이 확보된 시장은 저장한 같은 파일에서 다시 처리한다.
2. 같은 입력을 재처리해도 공개 목록과 종목별 변경 이력이 중복되지 않는다. 더 최신에 공개된 시장 목록은 이전 회차가 늦게 재실행돼도 유지된다.
3. 운영자는 시장·수집 기준일·입력 리비전으로 실패 실행을 찾아 원본 식별 정보와 실패 단계를 확인하고 그 실행을 재개할 수 있다.
4. 실제 종목 변경이 있는 회차의 공개가 확정 전에 중단되면 직전 최신 목록·정상 수집 시각과 변경 이력이 유지된다. 확정 후 실행 완료 기록 전에 중단되면 이미 공개한 결과가 유지된다. 두 경우 모두 재개 후에는 중단 없이 한 번 처리했을 때와 같은 종목 목록과 변경 이력을 조회할 수 있다.

### US-03 · 종목 변경 이력을 확인한다 (P2)

개인 사용자는 시장과 날짜로 변경 이력을 조회해 직전 정상본과 달라진 종목을 확인한다.

1. 여러 종목에서 변화가 감지되면 이력에서 종목별 시장·코드·유형, 변경 항목의 이전 값과 새 값, 수집 시각을 확인할 수 있다.
2. 정상본에서 종목이 빠졌다가 이후 정상본에서 다시 나타나면 `목록에서 미확인`과 `재등장`이 순서대로 기록된다.
3. 파일의 종목 데이터가 직전 정상본과 같으면 수집 성공 상태만 갱신되고 새 변경 이력이 생기지 않는다.

### US-04 · 코스피·코스닥 주요사항보고를 조회한다 (P1)

개인 사용자는 공시를 제출한 회사를 따로 지정하지 않고 코스피·코스닥의 주요사항보고를 날짜별로 조회한다.

1. 접수일에 두 시장의 주요사항보고가 여러 페이지에 걸쳐 있으면, 그날 수집에 포함된 전체 공시의 제목과 원문 링크를 조회할 수 있다. 정정 공시의 제목과 별도 접수번호도 보존된다.
2. 같은 접수번호가 서로 다른 조회나 재실행에서 반복되면 공시 목록에 한 건만 남는다. 뒤늦게 발견한 접수번호는 해당 접수일로 추가된다.
3. 한 시장의 조회 결과가 비어 있고 다른 시장의 페이지 조회가 실패하면 각각 0건 성공과 오류로 보인다. 실패한 시장·접수일을 다시 수집할 수 있고 기존 공시와 종목 스냅샷은 계속 조회할 수 있다.
4. 조회 중에 전체 페이지 수가 같더라도 동일한 접수번호가 페이지 사이에서 반복되거나 수집 건수가 응답의 총 건수와 다르면 해당 조회를 미완료로 기록한다. 미완료 묶음의 공시는 공개하지 않으며, 재개하면 첫 페이지부터 다시 모은다.
5. 공시 조회 중이나 적재 확정 직후 프로세스가 강제 종료되면 운영자는 기존 프로세스의 종료를 확인한 뒤 같은 시장·접수일·조회 리비전의 실행을 복구할 수 있다. 자동 재조회 범위 밖의 날짜도 지정할 수 있다. 복구 후 공시 목록과 해당 시도의 신규 적재 건수는 중단 없이 처리한 결과와 일치한다.

### 예외 상황

- 같은 코드나 심볼이 다른 시장에 있으면 시장별로 독립된 종목으로 적재하고 조회한다.
- 비어 있거나 형식이 깨졌거나 유효 건수가 비정상적으로 줄어든 파일은 시장 데이터 공개에 실패한 것으로 기록한다. 해당 시도의 파일 누락으로 종목 상태를 변경하지 않는다.
- 한 시장의 첫 수집부터 실패하면 정상본 미확보 상태와 오류 이유를 표시한다. 직전 정상본과 비교할 수 없는 시장은 변경 이력을 만들지 않는다.
- 공시를 조회할 때 기존 종목 마스터에 없는 종목도 공시의 시장과 종목코드로 보존한다. 공시 수집 성공 여부는 종목 마스터 갱신과 독립적으로 표시한다.

## 2. 기능 요구사항

- **FR-001** — 매일 다섯 시장의 원본을 자동 수집하고 시장별 파일 식별 정보, 수집 시각, 처리 건수, 검증 결과를 기록한다. 원천 효력일을 확인할 수 있으면 수집 시각과 구분해 보인다.
- **FR-002** — 정상 파일에 있는 주식·ETF·ETN을 모두 적재하고 시장과 종목 코드로 구분한다. 조회용 유형과 원본 유형·상품 구분 코드를 함께 보존한다.
- **FR-003** — 시장별 형식, 필수 항목, 중복 식별자와 건수를 검사하고 시장 데이터 전체가 검증됐을 때 그 시장의 최신 목록으로 공개한다.
- **FR-004** — 시장별 마지막 정상 목록과 수집 실패 이유를 조회할 수 있다. 실패한 시장은 직전 정상본을 유지하며 나머지 시장은 각자의 결과를 공개한다.
- **FR-005** — 종목 수집의 실패 실행을 시장·수집 기준일·입력 리비전으로 찾아 같은 입력으로 재개할 수 있다. 공개 확정 전 실패에서는 기존 최신 목록과 변경 이력을 유지한다. 확정 후 재개해도 입력당 공개 결과는 하나이며 이전 회차가 최신 목록을 되돌리지 않는다.
- **FR-006** — 각 시장의 직전 정상본과 비교해 신규 등장, 종목명 변경, 국내 거래정지 상태 변경, 목록 미확인, 재등장을 기록한다. 최초 정상본은 비교 기준을 만든다.
- **FR-007** — 매일 두 시장의 주요사항보고 전체를 접수일 기준으로 수집한다. 전체 페이지와 정정 공시를 포함한다. 같은 조회 중의 페이지 간 접수번호 중복과 총 건수 불일치를 감지하면 미완료로 처리하고 그 묶음의 공시를 공개하지 않는다.
- **FR-008** — 공시를 접수번호당 한 건으로 저장한다. 접수일·시장·종목코드·회사명·보고서 제목과 원문 링크를 조회할 수 있다.
- **FR-009** — 공시의 시장·접수일·조회 리비전별 상태, 실패 이유와 새로 적재된 건수를 보여준다. 결과 없음과 조회·검증 실패를 구분한다. 일반 실패와 확인된 강제 종료는 같은 조회 리비전으로 복구할 수 있고 다른 시도의 공시와 종목 데이터는 유지한다.

### 주요 데이터

- **수집 회차와 시장별 처리 결과** — 일정을 구분하는 회차, 각 시장의 원본과 검증 결과, 수집 시각, 마지막 정상본을 나타낸다.
- **종목 마스터와 변경 이력** — 시장별 종목 코드, 이름, 유형과 원본 코드, 관측한 변경의 전후 값을 연결한다.
- **공시 접수 정보와 수집 결과** — 접수번호가 가리키는 공시 제목과 원문 링크, 시장·접수일별 성공·실패와 신규 적재 건수를 연결한다.

## 3. 성공 기준

- **SC-001** — 정상 시험본 한 회차를 처리하면 수동 파일 다운로드 없이 다섯 시장의 결과를 조회하고, 주식·ETF·ETN의 원본 코드를 시험본과 대조할 수 있다. 확인 가능한 원천 효력일과 수집 시각을 별도로 검증한다.
- **SC-002** — 다섯 시장 중 한 시장이 실패해도 네 시장의 정상 결과가 공개되고 실패 시장은 기존 정상본을 유지한다. 실제 변경이 있는 입력을 공개 확정 직전과 직후에 각각 중단한 뒤 재개하면, 두 결과 모두 정상 실행과 종목 집합·변경 이력의 전후 값이 일치하고 입력당 공개 스냅샷은 1건이다.
- **SC-003** — 양 시장의 여러 페이지와 정정 공시를 적재하면 시험본 대비 누락과 접수번호 중복이 각각 0건이다. 페이지 수가 같은 상태에서 접수번호가 밀리거나 총 건수가 불일치하면 해당 조회에서 새 공시가 공개되지 않는다. 정상 묶음 복구 후에는 기대 접수번호가 모두 조회되고, 동일 묶음을 새 리비전으로 재수집하면 신규 건수는 0건이다.
- **SC-004** — 첫 페이지 0건과 중간 페이지 실패는 서로 다른 상태로 기록된다. 조회 중과 적재 확정 직후에 각각 강제 종료해도 같은 조회 리비전으로 복구하면 기대 접수번호 집합과 기록된 신규 건수가 중단 없는 실행과 일치한다.

## 4. 전제와 열린 결정

- 종목 마스터의 시장과 증권유형, 공시 수집 유형, 개인화의 제외 범위는 [PRD](PRD.md)를 따른다.
- 기능 구현 전에 마스터 건수 감소 판정 방식과 공시 재시도 정책을 정한다. 실제 파일·응답을 확인해 수집 시각, 건수 감소 운영값, 원본 보존 기간과 공시 접수일 재조회 범위를 일일 실행 활성화 전에 확정한다. 재실행과 공개 경계는 [기술 계획](plan.md)에 정리한다.
